# iMeet

Мобильный каркас приложения знакомств iMeet с голосовым вводом на Android.

Стек первого этапа:

- React Native 0.88.1
- Expo SDK 58
- TypeScript
- Expo Router
- Zustand
- Android release APK для внутренней раздачи

## Запуск

```bash
npm install
npm run start
```

Затем выберите iOS или Android в Expo CLI. Для прямого запуска:

```bash
npm run ios
npm run android
```

## Проверки

```bash
npm run typecheck
npm run doctor
```

## Сборка Android

Expo используется как React Native-фреймворк; EAS не обязателен для локальной проверки.
При установленном Android SDK и JDK 21 можно собирать APK через Gradle:

```powershell
npx expo prebuild --platform android --no-install
cd android
.\gradlew.bat :app:assembleRelease
```

Локальный release APK создаётся в `android/app/build/outputs/apk/release/`.
Для внутренней раздачи используется профиль `manager` в `eas.json`:

```powershell
npx eas-cli@latest build --platform android --profile manager
```

Он выдаёт подписанный release APK с JS-бандлом, который запускается без Metro.
Профиль `development` оставлен для проверки JS-изменений через `npx expo start --dev-client`.

## Native layout and fonts

Экран использует `useSafeAreaInsets` и `useWindowDimensions`: размеры Figma 412×852
являются базовыми токенами, но не фиксированным размером приложения. Нижний Tab Bar
учитывает системный нижний inset, а статус-бар получает светлый режим.

`expo-glass-effect` используется только когда Liquid Glass доступен на iOS 26+.
На Android и старых iOS используется прозрачный градиентный fallback с верхней
подсветкой и границей — без WebView и без непрозрачной заглушки.

Figma использует Gilroy, Manrope и SF Pro. Лицензированные бинарные файлы в проекте
отсутствуют, поэтому временный fallback — системный SF Pro на iOS и Roboto на Android.
Интеграционная точка `src/theme/fonts.ts` подготовлена через `expo-font`. Для точного
рендера нужно предоставить:

- `Gilroy-Medium.ttf`
- `Manrope-Medium.ttf`
- `Manrope-SemiBold.ttf`
- `SFProText-Semibold.ttf`

## AI Conversation

Главный экран собран из локальных ассетов Figma в `assets/figma` и компонентов в `src/components/ai-conversation`.

Для голосового ввода нужен Android APK с `@naslukh/speech-rn@0.1.0`.

1. Установите APK и откройте iMeet. Приложение сразу готовит GigaAM, скачивая модель (~163 МиБ), проверяя файлы и показывая прогресс. Naslukh 0.1.0 не предоставляет отмену загрузки.
2. Выберите голос Silero (по умолчанию `v5_5_ru · xenia`, меняется в Voice Lab) или системный TTS, нажмите «Начать общение» и разрешите доступ к микрофону. Произнесите фразу по-русски. После 2,5 секунды тишины или по кнопке «Закончить фразу» iMeet покажет распознанный текст и выберет ответ из локального сценария.
3. После окончания ответа iMeet автоматически включит микрофон. «Завершить разговор» прекращает прослушивание или озвучку. Последняя распознанная фраза и ответ остаются на экране.
4. Пока открыт экран разговора, приложение удерживает экран включённым. Для системной озвучки нужен русский голос движка Android. [Expo Speech](https://docs.expo.dev/versions/v58.0.0/sdk/speech/)

Анимация волны во время речи включается по событию VAD из Naslukh. Для реакции на громкость Naslukh нужен отдельный поток событий, например `onAudioLevel({ rmsDbFS })`, рассчитанный по уже захваченным PCM-кадрам и ограниченный примерно 10–20 обновлениями в секунду.

Для короткого подтверждения после 1 секунды тишины Naslukh нужен сигнал посреди той же реплики. Минимальный вариант — опция `backchannelSilenceMs: 1000` и событие `onVadPause({ sessionId, silenceMs })`, которое нативный модуль отправляет после приостановки захвата, сохраняя буфер реплики. Приложение произносит «Угу» и вызывает `resumeListenOnce(sessionId)` после окончания озвучки. Захват продолжится в рамках той же реплики до порога `vadMinSilenceSec: 2.5`. Тишину нужно измерять по захваченным кадрам, сбрасывая счётчик при возобновлении речи. Во время подтверждения микрофон приостановлен, поэтому слова пользователя в этот момент могут быть пропущены. В версии 0.1.0 работает только окончание реплики после 2,5 секунды тишины.

## Voice Lab и голоса Silero

Voice Lab открывается с главного экрана. В списке:

- Silero `v5_5_ru`: xenia, kseniya, baya, aidar, eugene — штатные голоса [RuVoice TTS](https://github.com/kost-t-human/ruvoice-tts);
- Silero `v5_cis_base`: ru_saida, ru_zinaida, ru_eduard — пак `cis_ru` (вариант `v5_cis_base_nostress`, лицензия MIT);
- Android TextToSpeech.

Четыре тестовые реплики: длинная с омографом «замок» и вопросом, эмоциональная, короткий вопрос и подтверждения «угу/ага». Каждый голос получает оценки ударений, вопросительной интонации, иностранного акцента и эмоций; они сохраняются через AsyncStorage. Экран показывает задержку до начала звука (событие onStart Android TTS: RuVoice синтезирует фразу целиком, поэтому задержка включает весь синтез) и PSS процесса iMeet. RuVoice работает в своём процессе, его память в PSS iMeet не входит.

Кнопка «Использовать в разговоре» сохраняет выбранный голос Silero для главного экрана. Если голос недоступен, разговор предлагает выбрать системный TTS.

### Интонации

В RuVoice по умолчанию уже включены все правила, влияющие на интонацию (вкладка «Правила»): «Интонация по типу предложения», «Логическое ударение» (сила 3 из 3), «Ударение в коротком восклицании», «Ударение в вопросе без глагола», «Разбор SSML». Выключать их не нужно. Остальное зависит от текста:

- ответы разговора размечены логическим ударением: ключевое слово вопроса в звёздочках (`*куда*`, `*город* или *природе*`); на экране и для системного TTS звёздочки снимаются (`stripFocusMarks`);
- вопрос и восклицание определяются по знаку в конце предложения, поэтому ответы короткие, с явными «?» и «!»;
- в Voice Lab есть пары реплик без выделения и с выделением для сравнения на слух.

Для меньшей задержки до звука в RuVoice можно включить «Быстрый старт» (по умолчанию выключен): первый кусок фразы синтезируется отдельно.

### Почему не v5_6_ru

У `v5_6_ru` та же таблица типов предложений (вопросы и восклицания есть и в 5.5) и один новый необязательный аргумент `emphasis` — выделение слова разметкой `**слово**`. RuVoice эту разметку не передаёт, поэтому через него 5.6 почти не отличалась бы от 5.5. Ноутбук `tools/silero-v56/build_ru56_pack.ipynb` не нужен и удаляется вместе с остальной чисткой. Модели Silero распространяются под некоммерческой лицензией; для продукта нужна коммерческая лицензия от Silero.

### Что убрано

Supertonic 3 (ошибки ударений, синтез 2,5–5 с на телефоне) и RHVoice убраны из Voice Lab и разговора; модель Supertonic больше не скачивается при запуске. Нативный модуль `modules/imeet-supertonic` пока остаётся в сборке: в нём же живут `IMeetDeviceTts` (озвучка внешним движком) и замер PSS. Классы Supertonic (`SupertonicEngine`, `SupertonicModel`, `SupertonicAccentDictionary`, `IMeetSupertonicModule` кроме `snapshot`) и `src/core/voice/supertonicTts.ts` не используются и удаляются вместе с переименованием модуля в отдельном шаге с пересборкой APK.

## Размер Android APK

Прежний development APK `ad6b6684` весил 399,2 МБ (380,7 МиБ). Он содержал четыре ABI и отладочный код. Текущий release APK `artifacts/imeet-voice-lab.apk` весит 59 793 612 байт (57,0 МиБ). Для него используется один ABI `arm64-v8a`, R8 и удаление неиспользуемых ресурсов. Сборка запускается без Metro; модель GigaAM загружается при открытии приложения. Большие модели не входят в APK. Для устройства с другим ABI потребуется отдельная сборка. На Windows `app.config.js` задаёт CMake 3.31.6, чей Ninja поддерживает длинные пути проекта. [Expo BuildProperties](https://docs.expo.dev/versions/latest/sdk/build-properties/)

Локальный APK подписан тестовым ключом и обновляет пакет `com.imeet.voicecheck` с сохранением его данных. Прежний `com.imeet.app` имел другую подпись; он удалён с телефона с сохранением данных (`adb shell pm uninstall -k com.imeet.app`). Чтобы вернуть именно этот пакет без потери данных, потребуется сборка с его прежним ключом подписи.
