# ТЗ для «Наслух»: события `@naslukh/speech-rn` для живого диалога

Заказчик: iMeet (голосовой AI-собеседник, Android, React Native + Expo SDK 58).
Текущая версия библиотеки в iMeet: `@naslukh/speech-rn@0.1.0`. Тестовое устройство: OnePlus 7 Pro (Android 12).

## Зачем

iMeet ведёт разговор циклом: `listenOnce()` → текст → ответ синтезом (внешний Android TTS) → снова `listenOnce()`.
Сейчас приложение узнаёт от библиотеки только «речь обнаружена» (через `addNaslukhProgressListener`) и итоговый текст
после паузы `vadMinSilenceSec`. Из-за этого невозможны три вещи, без которых разговор звучит не как с человеком:

1. **Поддакивание.** Пока человек рассказывает и делает паузу на вдох, собеседник вставляет «понятно», «ага» —
   не прерывая реплику.
2. **Волна по голосу.** Анимация на экране должна дышать вместе с громкостью речи, а не по таймеру.
3. **Перебивание.** Человек должен иметь возможность заговорить, пока агент отвечает: ответ останавливается,
   агент слушает.

Ниже — три независимых события. Порядок по сложности: 2 → 1 → 3. Обратная совместимость с 0.1.0 обязательна:
всё новое — необязательные опции и новые события.

## 1. Уровень громкости: `onAudioLevel`

Во время `listenOnce()` библиотека отдаёт уровень сигнала по уже захваченным PCM-кадрам.

```ts
type AudioLevelEvent = {
  sessionId: string;   // идентификатор текущего listenOnce
  rmsDbfs: number;     // RMS окна, dBFS (−90…0)
  peak: number;        // пик окна, 0…1
  speech: boolean;     // решение Silero VAD для окна
  timestampMs: number; // от начала захвата
};
engine.addAudioLevelListener(listener: (e: AudioLevelEvent) => void): () => void;
// опция listenOnce: audioLevelIntervalMs?: number  // по умолчанию 66 (≈15 событий/с), 0 — выключено
```

Требования:
- частота не выше 20 событий в секунду, считать из тех же кадров, что идут в VAD (без второго `AudioRecord`);
- не влиять на задержку распознавания; события не копятся в очередь при медленном JS-потоке (отбрасывать старые).

Приёмка: при речи в 30 см от телефона `rmsDbfs` заметно выше, чем в тишине комнаты; анимация в iMeet плавная,
нагрузка на CPU по профайлеру растёт не более чем на 2 %.

## 2. Пауза внутри реплики: `onSpeechPause` / `onSpeechResume`

Нужна короткая пауза, которая **не завершает** реплику.

```ts
// опция listenOnce:
speechPauseMs?: number; // например 700; должно быть меньше vadMinSilenceSec; не задано — событий нет

type SpeechPauseEvent = { sessionId: string; silenceMs: number; utteranceMs: number };
engine.addSpeechPauseListener(listener: (e: SpeechPauseEvent) => void): () => void;   // тишина ≥ speechPauseMs
engine.addSpeechResumeListener(listener: (e: { sessionId: string }) => void): () => void; // речь возобновилась
```

Требования:
- событие один раз на каждую паузу; после `onSpeechResume` счётчик тишины сбрасывается;
- **захват не останавливается**: буфер реплики сохраняется, итоговый текст `listenOnce()` содержит всю реплику;
- реплика по-прежнему завершается после `vadMinSilenceSec` тишины или `stopListenOnce()`.

Приложение в паузе может проиграть короткую реакцию синтезом. Чтобы она не попала в распознавание,
нужен п. 3.1 (эхоподавление); до этого iMeet будет реагировать только на длинные реплики и тихо.

Приёмка: фраза «Я недавно ездил в горы, (пауза 1 с) было очень красиво» при `speechPauseMs: 700`,
`vadMinSilenceSec: 2.5` даёт одно событие паузы и один итоговый текст со всей фразой.

## 3. Слушать во время ответа: перебивание

### 3.1. Эхоподавление

Микрофон должен работать, пока телефон говорит, и не слышать сам себя.

- источник `AudioSource.VOICE_COMMUNICATION`, где доступно — `AcousticEchoCanceler` и `NoiseSuppressor`;
- в `capabilities()` добавить `echoCancellation: boolean`;
- опция для старого поведения (без эхоподавления) — для сравнения качества распознавания.

### 3.2. Монитор перебивания

```ts
const monitor = engine.monitorSpeech({
  vadThreshold?: number;  // по умолчанию 0.6 — строже, чем у listenOnce
  minSpeechMs?: number;   // по умолчанию 300 — короткие звуки и эхо не считаются
  prerollMs?: number;     // по умолчанию 600 — сколько звука до срабатывания сохранить
});
monitor.onSpeech((e: { monitorId: string; speechMs: number }) => void);
await monitor.stop();

// продолжение реплики без потери первых слов:
await engine.listenOnce({ continueFromMonitor: monitor.id, vadMinSilenceSec: 2.5 });
```

Сценарий в iMeet: агент начинает говорить → `monitorSpeech()` → человек заговорил → `onSpeech` →
iMeet останавливает TTS → `listenOnce({ continueFromMonitor })` → в тексте есть и слова, сказанные в момент перебивания.

Требования:
- монитор и `listenOnce` не держат два `AudioRecord` одновременно — монитор передаёт захват в `listenOnce`;
- ложные срабатывания от собственного голоса телефона на громкости 60 % — не чаще одного на 10 ответов;
- задержка от начала речи человека до `onSpeech` — не больше 400 мс.

Приёмка: на OnePlus 7 Pro при громкости 60 % агент читает ответ 10 раз без участия человека — не более одного
ложного `onSpeech`; человек перебивает 10 раз — 10 срабатываний, первые слова есть в распознанном тексте.

## Общие требования

- Android 8+; события через тот же механизм Expo-модуля, что и `addNaslukhProgressListener`.
- Все подписки возвращают функцию отписки; события после `cancelListenOnce()` / `monitor.stop()` не приходят.
- Ограничение памяти D3 (старт запрещён, если свободно меньше 600 МБ) сохраняется.
- README: описание новых опций и событий, пример цикла «слушать — ответить — перебить».
